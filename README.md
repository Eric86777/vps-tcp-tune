# BBR v3 优化脚本 - Ultimate Edition v5.4.19

**XanMod 内核 + BBR v3 + 全方位 VPS 管理工具集**

一键安装 XanMod 内核，启用 BBR v3 拥塞控制，集成 33 项实用功能，优化你的 VPS 服务器。

> **版本**: v5.4.19：Xray 安装和更新时可选核心版本，默认稳定版 v26.3.27，也可选官方最新版（附客户端要求说明）。

### 自动配置开机恢复

若 `/usr/local/libexec` 已存在且权限为 `0700`，即使其中 helper 为 `0755`，非 root 的 Xray/Snell 仍无法执行它。新版只对 root 所有、非符号链接且其他账户不可写的目录补搜索权限（`0700` → `0711`），保留原有读写位，不开放目录列表。祖先目录异常、缺少搜索权限或挂载禁止执行时会准确报错，不自动改动 `/usr`、`/usr/local` 或挂载选项。

新装/更新 Xray、Snell 时先准备并核验启动检查依赖，覆盖已是最新版的路径；浏览菜单遇到缺依赖会警示并跳过迁移。Xray 配置按 systemd 实际运行用户安全保存，兼容 `User=xray` 和 `User=nobody`。官方安装器更新主服务及多个实例前逐份预检默认配置，启动前按更新后的身份同步所有者，保持配置字节不变；未知启动路径在停止业务前拒绝自动更新。

首次安装若在启动阶段失败，可能尚未执行官方的开机自启步骤。新版 VLESS、Shadowsocks 和双协议安装在完成前都会补齐并核验 `enable`，覆盖核心已是最新版而跳过下载的重试；失败机器重新进入安装即可完成。普通更新和专用迁移入口继续保持原有启用状态。

正常运行新版 `bbr` 时，会识别本项目已安装的 DNS 净化、Snell 和 Xray，自动补齐启动恢复；新装或更新 Snell v5/v6、Xray 时也会执行，包括检查后发现已是最新版的路径。仅在空机器浏览菜单不会创建恢复服务，`--help`、`--version` 及 Xray 专用卸载/只读检查入口也不会触发迁移。未知来源的 Xray 安装不会仅因服务名相同被自动接管。

迁移按实际文件检查，缺失的 helper、启动保护或新实例会补齐；重复执行保持相同文件内容，并静默重载 systemd 以重试此前失败的加载。显式安装/更新只处理目标代理，不因其它代理的自定义 guard 或无关 IPv6 检查而失败。自动迁移不下载或升级服务程序、不更换内核、不重启整机或网卡，也不启用或拉起用户手动停止的业务。启用辅助 timer 后可能运行定时检查；发现已受管、正在运行的 Snell 选用了坏本地 DNS 时，检查可尝试重启该服务。

需要单独检查、补齐时，仍可执行 `bbr --repair-boot-recovery`，或对已下载的新版文件执行 `bash net-tcp-tune.sh --repair-boot-recovery`。该入口可在尚未部署业务时显式安装恢复组件。

迁移会备份并移除本脚本旧版生成的 `systemd-resolved.service.d/dbus-fix.conf`；自定义同名文件会保留并报告冲突。Snell/Xray 启动前等待 DNS 冷启动就绪；探测超时会记录日志并交给代理自身处理目标和重试，避免把外部探针不可达变成所有 IP/内部域名业务的硬阻断。DNS 持久化恢复仍严格失败重试。定时检查同时核验受管启动文件和有效运行环境。DNS 净化只配置 DNS，回滚逐项恢复共享组件文件和 timer 状态，并保留后来新增业务所需的共享依赖。

首次部署或迁移后，应在维护窗口检查服务日志与实际域名请求；只有进程 `active` 不代表代理业务验证完成。永久禁用 IPv6 前若发现 ifupdown 仍配置 `inet6`，脚本会拒绝产生冲突；需要在有控制台和回退方案的情况下协调网络配置，代理安装不会代改网卡配置。

Xray 核心版本（菜单 13 → 1 安装、13 → 11 更新）：默认稳定版 v26.3.27，回车即可；官方最新版更新时菜单会列出，选择前会说明客户端要求并需输入 `y` 确认。v26.10.21 起 REALITY 拒绝不带抗量子密钥交换（X25519MLKEM768）的握手，mihomo 内核需 v1.19.31 及以上并导入菜单 15 的新链接（带 `support-x25519mlkem768=true`），旧链接和旧客户端会连不上；该版本的安全修复针对证书校验，本脚本生成的普通 VLESS-Reality / SS 节点用不上。已装版本高于稳定版时默认保持不动，也可在菜单 11 降回稳定版。跳过菜单直接指定版本：`XRAY_VERSION_OVERRIDE=v26.10.21 bbr`（可降级），跟随官方最新：`XRAY_VERSION_OVERRIDE=latest bbr`。配置父目录检查按 Xray 实际运行账号判断能否穿越，兼容官方创建的 `750 root:xray`。

Xray 安装登记与卸载安全检查分开：普通资源限制 drop-in 或旧运行身份不会在核心更新后被卸载白名单误挡。卸载支持本菜单生成的 VLESS、Shadowsocks 和双协议、对应订阅及官方 `copytruncate` 日志轮转，仍严格检查固定目录、服务钩子和 Snell 保护；未知自定义部署可能需要单独处理。

## 最佳实践流程（作者推荐）

这是经过多次实测总结出的**推荐**优化路径，建议按顺序执行：

> **懒人方案**：直接执行 **功能 66**（一键全自动优化），脚本会自动完成以下所有步骤。

### 第一步：安装内核

- 执行 **功能 1**：安装 XanMod 内核 + BBR v3
- **注意**：安装完成后**必须重启 VPS** 才能生效

### 第二步：BBR 调优（核心步骤）

- 执行 **功能 3**：BBR 直连/落地优化
- **如何选择**：
  - **小白用户**：选择 `1` (自动检测)，脚本会跑一次 Speedtest 并自动计算最佳参数
  - **进阶用户（推荐）**：如果你清楚自己的线路带宽，直接手动选择档位（如 `500Mbps` 或 `1Gbps`）
  - _作者经验：我自己一般手动选 500M 或 700M 档位，效果最稳_
- **地区选择**：带宽检测后会询问服务器主要服务的地区
  - **亚太地区**（港/日/新/韩）：标准缓冲区，适合大多数用户
  - **美国/欧洲**（跨太平洋/大西洋）：大缓冲区，解决高延迟路径的吞吐量瓶颈

### 第三步：DNS 净化（可选，慎用）

- 执行 **功能 5**：NS 论坛-DNS 净化
- **两种模式**：
  - `1. 纯国外模式`：Google + Cloudflare，强制 DoT 加密（**抗污染推荐**）
  - `2. 纯国内模式`：阿里云 + 腾讯 DNSPod，无加密（国内DNS不支持DoT）
- **安全说明**：已内置完整的事务性回滚机制（执行前全量快照 → 任意步骤失败自动恢复原始状态），重启持久化也已修复。如仍有顾虑，建议在有 VNC/控制台的情况下首次使用。

## 核心特性详解

### 1. Snell v5 多实例管理 (功能 12)

脚本内置了最新的 **Snell v5.0.1** 管理功能，提供比官方脚本更灵活的功能：

- **多实例支持**：可以在同一台机器上通过不同端口运行多个 Snell 节点
- **自定义配置**：支持自定义端口、自定义节点名称
- **一键修复**：菜单 12-4 自动补齐旧实例 systemd 防死锁、端口保留、每日重启兜底并恢复异常节点
- **智能更新**：保留低频核心程序更新入口，更新前也会补齐旧实例稳定性防护
- **双栈支持**：可选 IPv4 / IPv6 / 双栈监听模式
- **🆕 v6 RC 测试专区 (菜单 12-8)**：独立部署 Snell v6.0.0rc，与 v5 **完全隔离**（独立二进制 `snell-server-v6`、服务 `snellv6-*.service`、配置目录 `/etc/snell-v6/`、保留端口文件），互不影响。含安装/卸载/查看配置/更新+修复/健康检查/检查更新；安装时会先自检 v6 二进制，若官方包缺运行库，会自动或提示安装兼容依赖。配置默认写入 `mode = default`（流量混淆 + AES 加密，v6 的抗指纹特性），可按需改为 `unshaped`（关混淆仅加密，约快 10%）。⚠️ v6 仍是官方预发布(RC)，客户端需 Surge Mac Beta 渠道或 iOS TestFlight，App Store 正式版无法连接，建议仅用于测试节点

### 2. BBR v3 + 智能带宽优化 (功能 3)

基于 Google BBR v3 算法，配合脚本独家的**智能带宽检测**：

- 自动运行 Speedtest 测速
- 根据上传带宽自动计算最佳 TCP 窗口大小 (BDP)
- **地区选择**：支持亚太（RTT < 100ms）和美欧（RTT 150-300ms）两种模式，根据实际延迟自动计算最优缓冲区
- 动态调整 `rmem` 和 `wmem` 缓冲区，避免小内存机器 OOM，同时跑满大带宽机器性能

### 3. Caddy 多域名反代 (功能 32 子菜单)

全功能的 HTTPS 反向代理解决方案：

- **一键部署**: 自动安装 Caddy，配置 systemd 服务
- **智能检测**: 自动检测端口占用、防火墙配置、域名解析
- **SSL 自动化**: Let's Encrypt 证书自动申请和续期
- **多域名管理**: 轻松添加、删除、查看多个反代域名
- **安全备份**: 配置修改前自动备份，失败自动回滚
- **热重载**: 配置更新无需重启服务

**典型使用场景**:

- 用好线路 VPS 反代垃圾线路服务，加速访问
- 为 HTTP 服务快速添加 HTTPS 支持
- 多个后端服务统一使用 443 端口对外

### 4. 🆕 Cloudflare Tunnel 管理 (功能 32-6，v5.0.0 新增)

完整的 Cloudflare Tunnel 部署与全生命周期管理,无需开放 VPS 80/443 端口,自动 HTTPS:

- **一键安装**: 自动按架构(amd64/arm64/arm/386)下载 cloudflared + 引导 OAuth 授权
- **6 步部署向导**: 隧道名 → 反代目标 → 路由模式 → 域名 → 确认 → 自动执行
- **两种路由模式**:
  - _整站反代_: 域名所有请求转给单一后端(推荐,90% 场景够用)
  - _按 path 分流_: 支持多条 `/api → 后端 A` / `/web → 后端 B` 规则(前后端分离、多服务共域名场景)
- **失败自动回滚**: 任一步骤失败自动清理已创建的隧道 / DNS / systemd,不留孤儿
- **修改 ingress**: 选中隧道直接进编辑器改规则,保存后 validate 校验 + 自动重启,失败回滚到备份
- **完整删除**: 自动清理 systemd unit + CF 云端隧道(含强制删活跃连接)+ 凭证 JSON + 配置 yaml
- **账户切换/登出**: 轻松切换到其他 CF 账户
- **老配置自动迁移**: 从 `/root/.cloudflared/` 搬到 `/etc/cloudflared/` 并自动备份,已有隧道不中断

**典型使用场景**:

- VPS 没有公网 IP、被墙 443/80、想隐藏服务器真实 IP
- 自建服务通过自己的域名访问(Sub-Store / NAS 面板 / 内网管理界面)
- 不想花钱买 SSL 证书,让 Cloudflare 统一托管 HTTPS

### 5. 🆕 端口流量计费与到期管理 (功能 33)

基于 nftables 计数器/配额 + tc 限速,实现按端口的流量计费、配额管控与到期自动停机,适合合租/转售 VPS 端口的场景:

- **三种计费模式**: `double`(双向流量×2,适合全程走公网转发)/ `premium`(内网中转×1)/ `single`(仅出站×2)
- **端口三种粒度**: 单端口 / 端口段(如 `8000-8100`) / 端口组(逗号分隔,共享配额,合租场景)
- **配额与限速**: 月度流量配额(nftables quota 对象,达量自动阻断)+ 可选 tc 带宽限速
- **到期自动化**: 到期前 3 天邮件预警 → 到期当天自动停机 → 超期 3 天自动清理监控(过期封锁复用 quota 机制,瞬间生效)
- **计费周期重置**: 按"计费周期起点"而非"今天是否等于重置日"判定,自动补偿关机/cron 漏跑导致的错过重置
- **邮件通知(可选)**: 配置自己的 Resend API Key 后可收到到期/配额预警邮件,不配置则静默跳过,不影响封锁/重置等核心功能
- **诊断自愈**: 一键检测所有端口的规则/配额/定时任务状态是否正常

**典型使用场景**:

- 合租 VPS,按端口分别计费、设置到期日和流量配额
- 出租带宽/端口转发服务,到期自动停机无需人工干预

## 常见问题

**Q: 安装后运行 `bbr` 提示找不到命令？**

A: 请执行 `source ~/.bashrc` 重新加载配置，或者断开 SSH 重连即可。

**Q: 运行 `bbr` 提示 `curl: (22) The requested URL returned error: 401`？**

A: 通常是该机器旧别名或本机 `~/.curlrc` 带了异常 Authorization。请重新安装别名：

```bash
unalias bbr 2>/dev/null || true
unset -f bbr 2>/dev/null || true
bash <(curl -q -fsSL "https://raw.githubusercontent.com/Eric86777/vps-tcp-tune/refs/heads/main/install-alias.sh?$(date +%s)")
source ~/.bashrc
```

**Q: Snell 更新后旧版本还在？**

A: 请使用脚本菜单中的 **更新 Snell 核心程序**。如果是节点偶发不通，优先使用 **12 → 4 一键修复 Snell 不通/掉线**，它会重启需要恢复的实例并补齐旧节点稳定性防护。

**Q: 我的 VPS 是 ARM64（aarch64），能装 BBR v3 吗？**

A: 目前不能，这不是脚本的限制。BBR v3 至今未合入 Linux 主线内核，必须使用打过补丁重新编译的内核，而 XanMod 官方只提供 x86-64 构建，ARM 平台没有官方方案。**但 ARM 机器请直接使用功能 3**：ARM 内核自带 BBR + fq 队列算法，功能 3 的带宽检测与缓冲区调优在 ARM 上原生可用，同样能获得明显提升。功能 1 在 ARM 上会直接提示这一点。

**Q: 开启 BBR v3 需要重启吗？**

A: 是的，首次安装内核后必须重启服务器。后续修改参数（如功能 3）通常无需重启。

## Xray 安全卸载（菜单 13 → 12）

卸载为脚本内置逻辑，不联网、不自动安装依赖。支持默认目录中的临时 VLESS/Xray；发现其他协议、未知文件、目录链接/挂载、自定义服务钩子或停止联动时拒绝自动清理。公共日志轮转模板、共享依赖、Snell 和网络配置保留。

先输入 `卸载Xray`；程序会暂存文件、核对 Snell 文件/服务/进程/监听。原有 Snell 正在运行时，还需使用原客户端验证代理请求并输入 `Snell已验证`，之后才清除恢复材料。取消验证会尝试恢复 Xray；恢复失败会保留事务并明确报告。清除恢复材料后不保证能回滚。

独立入口绕过用户配置加载，适用于残缺安装及恢复：

```bash
sudo bash net-tcp-tune.sh --xray-uninstall-check     # 只读检查
sudo bash net-tcp-tune.sh --xray-uninstall           # 交互卸载
sudo bash net-tcp-tune.sh --xray-uninstall-resume    # 继续清理；早期中断先恢复
sudo bash net-tcp-tune.sh --xray-uninstall-rollback  # 恢复尚未清除的材料
```

需要 Linux/systemd、`/usr/bin/python3`（3.8+）和 `ss`；缺少工具会停止。恢复记录在 `/var/lib/net-tcp-tune/xray-uninstall/`（root 专用），新安装/更新会登记核心归属。跨文件系统、不受 systemd 管理的核心或无法确认归属的遗留布局需要人工核实，不会扩大删除范围兜底。旧 MTU 残留改在菜单 4 明确确认后清理，CF 老配置仍在 CF 管理入口迁移。
